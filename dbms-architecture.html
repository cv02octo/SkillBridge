🏗️ DBMS Architecture

Understand how different components of a DBMS communicate

📘 What is DBMS Architecture?

DBMS Architecture describes how a database system is organized and how users interact with the database.

It explains how the user request travels through different layers before reaching the actual database.

Simple Example:

When you search for a student's marks, your request goes from the application to the DBMS and finally retrieves the required information from the database.

🏢 Three-Tier Architecture

The three-tier architecture divides the DBMS system into three main layers.

1️⃣ Presentation Layer

This is the layer through which the user interacts with the system.

↓

2️⃣ Application Layer

It processes the user's request and communicates with the database.

↓

3️⃣ Database Layer

This layer stores and manages the actual data.

📚 Types of DBMS Architecture

1-Tier

User directly interacts with the database. It is commonly used for local applications.

2-Tier

Client communicates directly with the database server.

3-Tier

Client communicates with the application server, which then communicates with the database.

🌐 Real-Life Example

Imagine you are using a college student portal.

Step 1: You enter your roll number and password.

Step 2: The application processes your request.

Step 3: DBMS searches the database.

Step 4: Your student information is returned to the application.

📝 Quick Revision

  • DBMS architecture describes the structure of a database system.
  • 1-tier architecture directly connects the user with the database.
  • 2-tier architecture uses client and database server.
  • 3-tier architecture contains presentation, application and database layers.
  • 3-tier architecture provides better security and scalability.
